# CVE inventory

Public CVEs reported against FreeImage and FreeImageRe, and what FreeImageRe does about them. One line per CVE, sorted by CVE number, newest last.

| State | Meaning |
|---|---|
| fixed | A release or the current master no longer shows the defect. The reason names the commit or pull request, or the test: "A crashes, B does not" compares the FreeImage 3.18.0 base with a later version. |
| open | The defect is still present in master, or a fix is not merged yet (the pull request is named). |
| rejected | No change needed: not a defect in FreeImageRe, or not reproducible. The reason says why. |

**Release** is the first release that has the fix: a FreeImageRe release (the list starts at v4.0.0; the earlier tags v0.1 to v0.3 and v0.4-python are not counted, a fix from that time shows as v4.0.0), `FreeImage 3.18.0` for fixes made before the fork, and `master` for a fix that is merged but not released yet. For a fix found by running the sample without a commit that names the CVE, it is v4.0.0 when a v4.0.0 build (Win32 AddressSanitizer, same setup as for master) already handles the sample; the fix may be older. `-` means there is no fix in a release (`open`) or nothing to fix (`rejected`).

The **Sample** column links to the published sample files. They are not stored in this repository: [`TestSamples`](TestSamples/README.md) downloads them from where they are published, checks their SHA-256 and runs each in its own process (`TestSamples/run-samples.sh`), so every `fixed` and `open` line can be checked.

Checked against master `01995c0` (released version v4.2.1), Win32 AddressSanitizer build with all plugins that build here (LibJXR excluded), 2026-10-26. A reason of the form "no commit cites the CVE" means the fix was found by comparing versions with the sample, not by a commit message.
